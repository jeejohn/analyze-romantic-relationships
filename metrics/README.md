# Project metrics

Metrics exist to document real adoption and maintenance, not to manufacture eligibility.

Update `snapshot.json` from public sources after a release. Keep unavailable values as `null`, not `0`, when zero cannot be verified. Link evidence for use cases and contributor activity whenever privacy permits.

Recommended measures:

- GitHub Stars and Forks;
- clones or release downloads when available to maintainers;
- unique external issue authors and pull-request contributors;
- releases and closed reproducible issues;
- median first maintainer response time;
- verified use cases with permission to reference them.

Never buy engagement, create fake accounts, duplicate issues, or present private tests as independent public adoption.
